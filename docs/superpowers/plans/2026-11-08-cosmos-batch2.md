# Batch 2, track 1: the Cosmos space on key 0 — implementation plan

> **For agentic workers:** the kitchen runs Cook (in three waves; each cook writes only its dish's new files and tests) → Pass (one integrator per dish, in the order below, committing per dish) → Tasting → all gates → push → restart. Each dish is self-contained.

**Date:** 2026-11-08 · **Lane:** frontend · **Design:** [`docs/superpowers/specs/2026-11-07-cosmos-space-design.md`](../specs/2026-11-07-cosmos-space-design.md) · **Step 1** (pure modules) shipped in batch 1; this is step 2 (engine + Feed).

**Defaults until the owner answers the open questions:** re-key at import only when nothing references the minted id; paging off unless the render budget fails; Move to Recycle Bin only for dropped-in imports (enforced in main); a drop before any index is refused with "Index a folder first".

## Why

Batch 2 turns the Cosmos design (already on main: data rules, sticky ids, ten hq:cosmos:* rows, 127 pure-module tests) into a space that opens on key 0 and finds a picture in seconds. It is seven dishes with disjoint new files, cooked in three waves. Wave A (no dependencies on each other): (1) cosmos-index-engine, the pure indexing pipeline under dashboard/cosmos/ (walk, colour, hashes, duplicates, a 4-per-second throttle, the orchestrator) with injected IO; (2) cosmos-native, the Electron-bound adapters (dialogs, Recycle Bin, reveal, shell thumbnails first, nativeImage fallback with the BGRA to RGBA swap, a network-blocked hidden Chromium decode window fed with bytes as data: URLs so its canvas is never tainted) and an Electron-run check; (3) cosmos-search-core, ONE implementation of the source app's search grammar, sort, group and masonry layout plus a feed view-model in dashboard-v5/src/logic/cosmos-*.mjs, which the MCP tool hq_cosmos_search imports so renderer and MCP cannot drift; (4) cosmos-main, dashboard/cosmos.js plus store, curation, paths and import-local helpers (atomic sidecars with .prev and quarantine, validated intents, id-only path resolution with realpath containment, trash limited to dropped-in imports IN MAIN, the old-gallery union import). Wave B: (5) cosmos-ui-core, the live slice, vals, logic mixin and state keys, which need search-core. Wave C: (6) cosmos-ui-views, the two template fragments and their bindings test, which need ui-core; (7) cosmos-gates, an invented library generator (40 works by default, 1,000 on request), fake-preload paste, selftest states and cdp scenarios. Decisions that matter: ids are never re-derived (indexer reads the old idMap first, seeds from the manifest, assignIds appends); the renderer only sends ids and validated intents and receives file:// URLs computed once in main; a delete is shell.trashItem after an armed two-click confirm and, in this batch, main itself refuses anything that is not an imports: element (general delete waits for Cleanup); the decode window never draws a file:// source onto a canvas; no network, no new dependency, nothing listens. Two roadmap deviations are stated in the specs: the selftest imports the generator .mjs instead of a 400 KB JSON, and the cdp scenarios live in a new file that cdp-gate.mjs merges with one line. Layering fixed after review: lightbox z-index 990 (under the palette at 1000 so Ctrl+K still works), index overlay and import report 1060 (under What's new 1070), and the existing global button-sweep is protected from the 1,000-card Feed.

## Promises reviewers must try to break

- Path containment: for every id the renderer can send to trash or reveal, the absolute path is resolved in main from relFor(idMap, id), is rejected when rel is absolute, has a drive letter, UNC, '..', NUL, a ':' other than the imports: prefix (so retired:<id> never resolves) or an 'imports:' remainder with separators, and is re-checked after realpath with path.relative (C:/root-evil is not inside C:/root; a symlink or junction in the root pointing outside is refused). No handler accepts a renderer-supplied path for a read or a delete; importFiles copies FROM arbitrary absolute paths but to a destination computed only in main.
- Decode in one place: grep dashboard/cosmos.js and dashboard/cosmos/*.mjs for decodeURIComponent and find it only inside ids.relFromSrc; a literal %41 in a file name never retargets a delete.
- No network of any kind: no http/https/net/dns/tls/child_process/fetch in the new main-side sources (a test greps); the hidden decode window cancels every non-file/data/blob request and denies all permissions (the native check proves a request is cancelled); the decode window keeps webSecurity on and never draws a file: URL onto a canvas (unit-asserted, and the Electron SVG case proves the data: route is not tainted); the MCP tool and renderer make no request; nothing binds or listens; no new npm dependency (package.json files unchanged).
- Ids never move: the sticky-id regression (a newer colliding file does not take a curated file's bare id) passes through the real indexer and the e2e; re-index twice with no changes yields byte-identical idMap and works; a deleted file keeps its idMap entry; the ONLY id change anywhere is the reported re-key at import-local, which refuses any id that curation or cleanup references and reserves the retired id as retired:<id> forever (round-trips parseIdMap, cannot be favourited, hidden or tagged through apply, cannot resolve to a path).
- Curation is never lost: every curation write copies the previous good file to curation.json.prev first; a corrupt file is quarantined (*.corrupt, -2, -3), the read returns an honest {error}, and nothing overwrites it with an empty document; a crash between tmp write and rename leaves the old file; a library that will not parse is moved aside and its idMap salvaged; import-local is a union (existing wins) and never replaces without the second Yes + token; trashing a file removes only the work from library.json, never idMap, favourites, clusters or overrides.
- Deletes: only shell.trashItem (Recycle Bin), only after the owner's second click on an armed inline confirm, and MAIN itself refuses (failed row, deps.trash never called) any id that is not an element dropped into data/cosmos/imports in this batch, at most 20 ids a call; the renderer removes an element only for ids in trashed[]; failed[] shows main's message and keeps everything; no unlink, no spawned shell, no window.confirm anywhere (grep).
- The vault is never written and nothing outside data/cosmos/ is written by this space: the indexer only reads the folder (read-only fs calls in the injected io; a test asserts no write call receives a path under the root), the native check writes only under os.tmpdir(), and the MCP tool lists the data dir before/after to prove it wrote nothing.
- The 4-per-second cap: any sliding 1,000 ms window of hq:cosmos:index-progress pushes contains at most 4 events including the final done_all (fake-clock test over a 5,000-file run); the final push always arrives; cancel leaves the old library untouched.
- Honest states: every state in design section 7 has its own exact block and reason (offline, loading, error with kept copy, no-root, empty-library, no-match, no-favourites, root unreachable, stale, indexing, scrubbed); null vs [] works are never confused (a Feed must not say 'no elements' while a read is in flight); no success toast that main did not confirm; thumbnails that failed render from the original; a work whose real size is unknown (approx) never shows invented pixel dimensions and is never flagged tiny.
- The render budget: 1,000 cards, first render <= 400 ms, median unchanged-result re-render <= 40 ms (memo hit), narrowing keystroke <= 150 ms, zero layout work while off the tab (vals return one frozen object, spy count unchanged); every card is emitted with lazy images (no windowing, per design) and 'Show N more' exists and works whether or not FEED_PAGE is enabled. The global button-sweep still finishes inside its 900000 ms timeout with the Cosmos screen added (default fake library 40 works, card buttons capped), and its CLOSED state resets cosLb/cosIdx/cosReportOpen/cosReplaceAsk.
- Keys and layers: /, f and the arrows act only while the lightbox is open (palette, focus mode and snapshot scrub unchanged otherwise, with regression rows); the lightbox sits at z-index 990, UNDER the palette (1000), so Ctrl+K opens the palette on top and Escape closes the palette first; the index overlay and import report sit at 1060 under What's new (1070) and over settings/cheat (1050); key 0 reaches the tenth destination with no key-handler change; the palette lists the tenth destination with hint 0 and its Go-to cap is NAV.length.
- No owner data in fixtures: the generator and every test use invented names (alpha-site, beta-shots, placeholder-library), data: URI thumbnails and synthetic header bytes; a test scans the fixture output for Users, ROG, Pictures, Documents and drive letters; no path, thumbnail or manifest entry from the owner's pictures enters the repo; data/cosmos/ stays gitignored and pinned.
- Colour honesty: a known flat red PNG, a JPEG made at run time, a teal SVG and a WebP all return the right hex through the real nativeImage and decode-window paths (a BGRA-swapped result fails the Electron check, and HQ_COSMOS_CHECK_BREAK=bgr proves the check can fail); formats nothing can decode give thumb:null and the Feed still shows them from the original; the main process is never blocked more than 750 ms by a thumbnail (shell and async paths first, native-file only up to 25 MB).
- One search grammar: the MCP tool imports the renderer's cosmos-search.mjs (a test calls both on the same input and compares, and server.test runs the tool through the real server from a temp root with the copied dependency files); the purity scan proves the module has no DOM/network references; the copied constants (types, normalizeTag) are pinned to the main-side originals by a parity test; hidden elements never appear in hq_cosmos_search results and no absolute path leaves the MCP tool.

## Open questions (defaults above until answered)

1. **Should import-local be allowed to re-key an indexed id to the old gallery's manifest id when the owner indexes BEFORE importing (their documented order)?** The design says the indexer seeds ids from the manifest on the first run, the owner steps say index first and import second. Without a re-key those two cannot both hold. _Recommended:_ Yes, restricted: only when no curation or cleanup references the minted id and the manifest id is unused; the minted id is reserved forever as retired:<id>; everything is reported. The alternative (refuse and report mismatches) loses curated favourites for any file whose slug drifted since the manifest was written; the other alternative (tell the owner to import first) contradicts the owner steps already agreed.
2. **Should the render budget ship with paging on (FEED_PAGE = 250, 'Show N more') or off (all 1,000 cards)?** The roadmap asks for a named median with paging as the fallback; the real number only exists once the space renders in the Electron gate on this machine. _Recommended:_ Off by default (design section 8: every card emitted, lazy images). The cosmos-render-budget scenario decides at the Pass: if the budget (first render <= 400 ms, unchanged-result re-render median <= 40 ms, narrowing keystroke <= 150 ms) fails, flip FEED_PAGE to 250 and keep it only if the paged variant passes.
3. **Is 'Move to Recycle Bin' limited to dropped-in imports for this batch (enforced in main, not just the UI), with general delete waiting for Cleanup?** Keeps this batch's delete surface to files the app itself copied into data/cosmos/imports, even against a buggy or compromised renderer. _Recommended:_ Yes. Main refuses any non-imports id in trash(); the engine's resolution and partial-failure handling are fully tested, so Cleanup only removes one guard and adds UI.
4. **Should dropping files before any folder is indexed be refused ('Index a folder first') or create an imports-only library?** Keeps the honest-state table small and the sticky id map single-rooted. _Recommended:_ Refuse with that sentence. An imports-only library would add a third library state and a root-less walk that the first real index then has to merge.

## The dishes

### Dish 1: Indexing that is fast, resumable and never renames a picture (`cosmos-index-engine`, L)

**Serves:** Index the pictures folder once, then every open is instant; the owner's curated favourites and clusters must still point at the same images after every re-index.

**Why now:** Key 0 is empty without an index, and this is the only half of the engine that can be built and tested completely in plain Node with fake IO. ids.mjs and imagesize.mjs already exist on main (dashboard/cosmos/ids.mjs:153 assignIds, :117 seedFromManifest; imagesize.mjs:232 imageSize), so the orchestrator is mostly composition. Wave A: needs nothing from the other dishes.

**Spec:**

All files are pure ESM under dashboard/cosmos/ with every side effect injected. Port behaviour (not code) from the read-only source app C:/Users/ROG STRIX/Documents/retrogallery/src/lib: colorExtract.ts (the quantizer only, not loadImage/scanCache), dhash.ts, duplicateClusters.ts.

walk.mjs: `async walk({roots, io, isCancelled, yieldNow, limits})` where roots = [{prefix:'', dir:<root>}, {prefix:'imports:', dir:<data/cosmos/imports>}], io.readdir(dir) -> [{name,isDir,isFile,isSymlink}], io.stat(abs) -> {size,mtimeMs,birthtimeMs}. Yields {files:[{rel,abs,ext,size,mtimeMs,createdMs,kind:'image'|'video'}], skippedDirs, unreadable:[count], truncated}. Rules: extension allowlist = IMAGE_EXT union VIDEO_EXT from ./infer.mjs (lower-cased compare); skip directory names `_clips node_modules .git .obsidian .trash .thumbnails $RECYCLE.BIN System Volume Information` (exact, case-insensitive) and never follow symlinks or junctions (isSymlink entries are skipped, so the walk cannot leave the root); max depth 32; max 200000 files (beyond it stop and set truncated:true, never crash); an unreadable directory is counted, not thrown; rel always uses '/' and for the imports root is `imports:<file name>`; result sorted NEWEST FIRST by mtimeMs, ties by lower-cased rel; `await yieldNow()` every 200 entries; isCancelled() checked per directory and returns {cancelled:true}.

colorextract.mjs: `extractColors(rgba32)` where rgba32 = {width,height,data:Uint8Array RGBA} (the caller guarantees RGBA, NOT Windows BGRA; document that in the header and say the swap lives in cosmos-native). Returns {color:{hex,r,g,b,h,s,l}, palette:string[<=5]} or null for empty or fully transparent input. Private helpers for hex/hsl (do not import the renderer tree).

dhash.mjs: DHASH_WIDTH 9, DHASH_HEIGHT 8, NEAR_DUPLICATE_THRESHOLD 10, `dhashFromGray(gray9x8:Uint8Array(72))` -> 16-char lowercase hex, `hammingDistance(a,b)` (null if either is not 16 hex chars), `isNearDuplicate`.

dupes.mjs: `clusterDuplicates(works, {threshold})` (union-find over exact contentHash edges and near perceptualHash edges; members>=2; kind 'exact' if any exact pair; memberKind per member; suggestedKeeperId = largest pixel area then newest createdAt then lowest id, where a work flagged `approx` counts as area 0; reason sentence; `clusterKey(c)` = sorted ids joined by a single space), `detectLowQuality(works)` (tiny: min(width,height)<64 or area<4096; blank: color saturation<0.03 and palette length<=1; only works with a MEASURED size (not `approx`) and a color are considered for tiny, only works with a color for blank), and `async clusterDuplicatesAsync(works, {yieldNow,isCancelled,onProgress})` which does the O(n^2) near pass in chunks of ~400 rows with a yield between chunks (a 5,000-work library must finish with >=10 yields). Output shape stored in library.json `dupes`: {exact:[{key,ids,keeperId,reason}], near:[...same], junk:[{id,reason:'tiny'|'blank'}]}.

throttle.mjs: `makeThrottle({now, emit, minGapMs:250})` returning {push(p), flush()}; coalesces to the latest value; emits at most 4 events in ANY sliding 1000 ms window INCLUDING the final one: a payload with done_all:true is never dropped and never earlier than the next free slot (trailing-edge), and flush() after the final delivers pending state at its slot. No timers inside: the caller passes now() and calls push on its own progress ticks; a `drain()` promise helper waits for the slot using an injected sleep.

indexer.mjs: `async runIndex({roots, rootLabel, io, oldLibrary, manifest, now, yieldNow, onProgress, isCancelled, concurrency=3})`. io = {readdir, stat, readHead(abs,n)->Uint8Array (first imagesize.HEADER_BYTES), hashFile(abs)->hex sha256, thumbnail(abs,{ext,kind,edge:560,size})->null|{jpeg:Buffer,width,height,sourceWidth:number|null,sourceHeight:number|null,rgba32,gray9x8}, thumbInfo(id)->null|{mtimeMs}, writeThumb(id,Buffer)}. `width/height` of the thumbnail result are the THUMBNAIL's own size; `sourceWidth/sourceHeight` are the original's size when the strategy knows it (native-file and chromium do, the Windows shell does not) and null otherwise. Steps, in this order: (1) idMap = parseIdMap(oldLibrary && oldLibrary.idMap).map; if oldLibrary is null/has no idMap AND a manifest object is supplied, seedFromManifest(manifest, idMap) first (first run only; report seeded/skipped counts in stats); (2) walk; (3) assignIds(idMap, files) (the sticky rule: known paths keep ids; new paths minted newest first); (4) phase 'thumbs': per file, if the old work for that id has the same size and mtimeMs and thumbInfo(id) exists and is not older than the source, carry the old work over untouched (skip, count it); else read the header (imageSize/orientedSize; videos have none), call io.thumbnail (errors are caught per file and become thumb:null), compute extractColors(rgba32) and dhashFromGray(gray9x8).
