# Batch 3: reachable and honest (grabs into Cosmos, Today ribbon, Brief mailbox and history, vault template, Machine drift)

Date 2026-11-11. Lane: frontend (shared edits announced in docs/sync/HANDOFF.md). Roadmap: docs/superpowers/specs/2026-11-07-personal-roadmap-design.md. Started from main @ 6f32be7.

## Why

Batch 3 makes what the owner already collects reachable and honest: a grab lands in Cosmos without a second step and a session can find it (grab-into-cosmos, library-find); Home answers "where did today go" from logs the app already keeps (today-ribbon); a Claude session can clear a handled Brief row through a hardened file mailbox, the Brief remembers what it noticed and how each thing ended, and says so honestly when nothing needs the owner (brief-mailbox, brief-history); a chat becomes a vault note in two clicks with no model running (vault-template); and System > Machine shows how the PC drifted (machine-drift). Seven dishes, because the grab dish is split so each stays at most L; nothing outbound, nothing needs an LLM, no edit to ~/.claude, collector/, schema/, spellbook/, run-pipeline.ps1 or the vault. The real refresh from a session stays OUT: it is blocked on the structure lane adding an assemble.mjs flag (for example --no-vault) that reads the previous report, writes only data/latest.json and skips the Workspace Status write and the daily-note injection; until then hq_scan_trigger stays collector-only. Anchors were re-read in the code and then re-checked against a critic pass; the plan follows the code where it differs from the roadmap text (see changes).

Measured use since batch 2 shipped: no surface use marks yet and a handful of MCP reads, so the order follows the roadmap, not use.

## Tasting promises

- A grab only crosses into Cosmos after the owner's own Save click: with no click there is no POST, no new file in data/cosmos/imports, and the Downloads original is still there after a grab (copy, not move).
- POST /library/grab refuses without the paired token and origin, refuses a path outside Downloads/WorkspaceHQ/grabs (including a symlink or junction out of it), refuses an SVG or an HTML file renamed .png, refuses over 64 MB, and a repeat grab of the same bytes changes nothing (same clip-<hash12> name, duplicate:true); nothing is written outside data/cosmos and cosmos.js stays the only writer of library state.
- A clip appears on key 0 with the clipped tag, its source host and up to three title words; its type reads as path-inferred (misc, photo or motion) and the plan says so rather than faking a type; it can be moved to the Recycle Bin like any dropped file; hq_library_find with site and since returns it with an imports: rel and one importsFolder, a library work with only a root-relative path, and never bytes, thumbnails or a page URL with a query.
- The Today ribbon says only what its sources can: a stretch with no day-log line is 'app not running (unknown)', never 'asleep'; the browser lane says it is kept for 3 days instead of drawing zeros; no domain, commit message or path reaches the model; and hq_today returns counts with their age and cannot answer a day other than today.
- A Claude session can dismiss a med or low top-three Brief item by ref and nothing else: a key, an index or text is refused before any file is written; an overflow, standing, high-severity or secrets row is refused in words and never answered as dismissed; a dismissal that changed nothing is never reported as done; the app closed (no heartbeat, a stale one or a dead pid) answers at once and queues nothing; a forged, oversize, stale or symlinked request is ignored; a .taken found at startup is never re-run; the 11th dismissal in an hour is refused; no answer or audit line carries a ref, key or item text.
- The Brief never calls an ending fixed when it cannot know: a row whose source erred or went stale closes as 'went silent', a row whose key merely changed closes as 'changed', a row pushed below the visible list stays open, a cold start closes nothing, dismissed rows are worded as dismissed, and the all-clear card shows once per clear episode, only when items, overflow, standing and hidden rows are all empty, no source errored and the brief is fresh; it does not show for a silence-only or change-only clear.
- Save to vault with no model running reaches a preview and then exactly one note: the template path never calls the LLM, the preview writes nothing, one note lands under 30_Areas/Claude/<Project>/ only on the owner's Save click (HQ_VAULT_DIR in tests), a secret in the chat is masked twice, and chat text cannot start a heading, a frontmatter block or a vault link.
- Machine drift draws gaps, not zeros: a ping or update-days of 0 is a gap, the temp series is titled Temp files (GB) because that is what the collector stores, there is no GPU driver or GPU temperature series, the disk estimate refuses with fewer than 8 checks or under 14 days and never says 'will run out', and a partial disk snapshot never produces a growth line.
- No new network surface: the only HTTP added is the existing 127.0.0.1 bridge; no dish calls out, none needs an LLM, none edits ~/.claude, collector/, schema/, spellbook/ or the vault, and a privacy scan of everything added reports 0 names, 0 secrets and 0 owner paths.

### brief-history (M): Brief history and the all-clear moment

**Serves:** Brief track: what the Brief noticed and how each thing ended (resolved, dismissed, acted on, changed, or went silent), and an honest one-time all-clear when nothing needs the owner; the standing highs have held the top since 2026-11-05, so this pays off when they clear.

**Spec**

WHY A LEDGER FILE. The roadmap built this on brief-state.json firstSeen. In the code firstSeen cannot be the history: brief.js drops a key that has been off the brief for an hour (FIRSTSEEN_GAP_MS), prunes anything not live for 7 days (FIRSTSEEN_KEEP_MS) and caps at 200, so a resolved item disappears from it within the hour. The ledger is therefore its own small file data/brief-ledger.json { v:1, open:{ <ref>:{ rule, source, severity, first, last, acted? } }, closed:[{ rule, severity, count, first, ended, how }], lastClearShownAt }, keyed by the 12-hex ref (refOf from brief-project.mjs), never by the raw key, so it holds no project, bill or branch name; wording always comes from brief-project's WORDING table by rule id. Closed entries are kept 30 days, at most 300; atomic write; a corrupt file is moved to .corrupt and never emptied silently. data/brief-ledger.json gets its .gitignore pattern and OWNER_DATA pin (and its .tmp) before any code.

WHAT A BRIEF CAN AND CANNOT SHOW (verified in brief-core.mjs and brief.js, which is why the first draft's classification was rewritten). brief.json exposes items (3), overflow (rows 4 to 12), standing and a count 'more'; a row ranked below 12 is in none of them. And the key is rule:subject:value, so a changed value or count makes a NEW key: the old key leaves and a new one opens for the same rule. A key leaving the live set therefore does NOT mean the thing was fixed.

CLASSIFICATION (dashboard/brief-ledger.mjs, PURE, table-tested). observe(ledger, brief, { now, dismissedKeys, errors, coldStart }) runs after each computation (brief.js compute(), after decorate so the additive acted:{verb,at} marker is visible): every live row (items, overflow and standing) is opened or has last refreshed. An open ref that is no longer live is decided in this order, first match wins: (1) its key is in brief-state.json dismissed: 'dismissed'; (2) hidden rows exist (more minus overflow length is above 0): it stays OPEN, because a row pushed below rank 12 is invisible, not gone; (3) another live row carries the same rule: 'changed' (the fact moved on to a new key; this is never counted as resolved); (4) its last-seen row carried acted:{verb,at}: 'acted'; (5) its source is not trustworthy this computation: 'silent' (a quiet source cannot be called fixed); (6) otherwise 'resolved'. Source trust uses an ALIAS TABLE in brief-ledger.mjs because the vocabularies differ: item sources are scan, scan-run, money, claude, pc-health, github, vercel and claude-code while error sources are scan, pc-health, money, claude, brief-senses and brief; the table maps scan-run to scan and github, vercel and claude-code to brief-senses; an error source 'brief' (the file write failed) or any error whose source is not in the table makes every close 'silent' that computation; scan-sourced rows are also 'silent' while a scan-stale or scan-failed row is live. A test greps every source literal in brief-core.mjs and brief-senses.mjs and fails if one is missing from the alias table. Residual, stated honestly: a senses row (github, vercel, claude-code) whose data file went old without an error is not detectable, so it can still close as resolved. The first computation after an app restart closes nothing (no 'resolved' from a cold start with half-loaded inputs): it only re-opens. An open entry not live for 30 days with hidden rows is closed 'silent'.

THE ALL-CLEAR. The Brief panel already has an honest empty line (vals/brief.js brfEmpty: ready, no items, none overflowing, no source errors; its text says 'Nothing new right now' when standing rows exist). The all-clear card is stricter and shows ONCE per clear episode: items, overflow AND standing all empty, hidden rows zero, no source errors, brief fresh (not stale), and at least one row closed as resolved or acted since the last time the list was non-empty; it lists what got resolved in rule wording ('A project had work not pushed - resolved Thu after 2 d'), then lastClearShownAt is set by an explicit ack call so it never repeats until the Brief has had something again. A clear that is only silence, change or dismissal never shows the card. The Brief footer shows 'N cleared this week' (resolved plus acted in the last 7 days); dismissed rows are counted separately and worded as dismissed, never as fixed, and changed rows are not counted at all.

WHERE IT SHOWS. History > Timeline gets an Operator section above the weeks (an include of a new brief-history.tpl.js fragment, no new History sub-view, so catalog.mjs SUBS and the quick-jump parity test do not move): rows like 'Work not pushed on a project: noticed Tue 09:12, resolved Thu after 2 d' for the last 14 days, one row per closed entry and one per still-open fact, with the way it ended in words. dashboard/brief-ledger.js (main, new; wired into brief.js init as a dep so main.js changes only inside the existing briefApi call): load/save, IPC hq:brief-history:read -> { entries, clearedThisWeek, dismissedThisWeek, allClear: null | { since, resolved:[{ text, after }] } } and hq:brief-history:ack. ### machine-drift (M): Machine drift: how the PC changed, and what filled the disk

**Serves:** Brief track: the disk has been the Brief's standing high for days; System > Machine should show how the PC moved over weeks and what grew, from history the collector already keeps, with no GPU driver age until the structure lane enumerates the GPU.

**Spec**

WHAT THE DATA REALLY IS (verified in data/pc-health-history.json and collector/lib/pc-health.mjs historySample, which the structure lane owns and this dish never edits). The history is a rolling window: HIST_MAX is 96, so the charts say 'last N checks'. at is a zone-less LOCAL time string, so it is parsed as local. Series per row: cpu, ram, diskFreeGB, startup, temp, pingMs, updateDays, gpuDriverDays, plus gpuTempC and battery on newer rows. Two corrections to the roadmap: temp is TEMP-FILES GB (m.tempGB), not a temperature, so that chart is titled 'Temp files (GB)'; and pingMs and updateDays are written as 0 when unknown (the collector's '?? 0'), so a 0 there is a gap, never a zero point. gpuDriverDays (and gpuTempC, which follows the same flipping adapter) are left out entirely until the structure ask lands (the GPU enumeration ask in HANDOFF is unchanged).

THE CHARTS. dashboard-v5/src/live/machine-history.mjs (PURE) turns the rows into seven small charts: free disk, RAM, CPU load, temp files, ping, startup apps, days since updates. Each chart shows its sample count and date span, draws a gap (a break in the line, never a zero) where a value is missing or 0-meaning-unknown, labels the unit, and never smooths. An opt-in 'Estimate' button on the disk chart fits a straight line to diskFreeGB and refuses (and says why) unless there are at least 8 checks over at least 14 days and the slope is downward; when it answers it says 'at this pace there would be about N days of room, if nothing changes' - never 'will run out' (a honesty.test denylist entry). Rendering is SVG with a text twin, tokens only, phone width.

WHAT FILLED THE DISK. data/pc-health-disk.json is the collector's folder-size breakdown, a latest snapshot overwritten at most every 6 hours (items[{path,label,gb}], partial:true while some folders are unmeasured); it holds no history, so a new main-side module dashboard/disk-history.js keeps one daily copy in its own new file data/disk-history.json { v:1, rows:[{ day, at, partial, items:[{label,gb}] }] } (labels and GB only, never paths; same-day row replaced, at most 120 days, atomic, corrupt moved aside). It ticks on startup, every 6 h and when pc-health-disk.json changes, never reads at boot beyond that, and writes nothing else. A line like 'A folder +N GB in 7 days' is computed only from folders measured in BOTH rows and only when both rows are complete for that folder; otherwise the panel says 'needs two days of readings' instead of guessing. The Brief's disk row why-line is NOT changed in this dish (brief-core stays untouched; recorded as a later step) so the Brief goldens and the other brief dishes do not collide. data/disk-history.json gets its .gitignore pattern and OWNER_DATA pin before any code.
