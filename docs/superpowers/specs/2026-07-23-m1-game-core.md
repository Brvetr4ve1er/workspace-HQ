# M1 — GAME CORE (economy v2)

Milestone spec per the NEXUS v3 charter (`2026-07-21-nexus-v3-program.md`,
PART III "Game economy v2"). Gate: M0 (landed 2026-07-22). Split: the four
economy batches are **structure-lane work** (each = one CONTRACT.md *Pending
changes* entry + golden re-baseline, per program invariant 2); the voice-pack
layer is **frontend** (landed with this spec — `dashboard-v3/src/lexicon/
voice/`). Nothing here resets or rewrites `account.xp` — it stays lifetime-
monotonic forever.

## Batch 1 — CANONICALIZE (behavior-preserving)

1. Set `grace_hours: 36` in collector config FIRST as a no-op (current
   effective behavior), THEN wire the streak computation to read it. Order
   matters: wiring a default of 24 before the config lands would kill the
   user's live streak overnight.
2. `build-data.mjs`: project a `GCFG` block into `window.DATA` — level curve,
   quest-tier XP table, decay thresholds, mastery day-tiers, blessing
   thresholds. Thresholds become *data*; the v3 renderer then deletes its
   duplicated tables (fe follow-up: `MASTERY_TIERS` in grimoire/view.js,
   `BLESSING_THRESHOLDS` in legacy/view.js are the two known copies).
3. Move the Scadutree-blessing derivation collector-side (fe currently
   derives it at render; the collector owns one truth, renderer reads it).

## Batch 2 — BANKING

4. Bank achievement XP into `account.xp` and wire the 6 vestigial milestones.
   **Stacking policy:** a milestone pays only when no quest paid the same
   concern in the same scan (no double-dipping one fix).
   **Grandfather policy:** already-unlocked achievements back-pay 0 via a
   single `notify:false` migration event — no retroactive level spike, no
   celebration storm (the fe takeover already dedupes by change-set
   signature, but the data must not emit the storm in the first place).

## Batch 3 — JUICE (deterministic, no RNG)

5. Seeded crit rolls on quest-completion XP only — date-hash primitive (same
   family as spell-of-the-day / voice-pack picks: pure function of scan id).
   New `changes_since_prev` type (`crit`) must be guarded in BOTH renderers
   (v2 app.js AND v3 fx.js) before the collector emits it.
6. Same-day combo: requires persisting completion *times* (not just dates) in
   `data/quest-overrides.json` — contract entry required. Rules stay pure
   functions of (previous scan, today's inputs).

## Batch 4 — META (split ledger)

7. `account.xp` untouched (levels/trends stay monotonic). NEW spendable
   `account.runes_balance`; purchases live in a main-owned runtime file
   (`data/purchases.json`, shards.json pattern — gitignored, don't
   schema-validate).
8. Unlocks fed by the balance: Cosmetic Shop (shard skins, stat-card frames,
   **voice packs** — the fe loader at `src/lexicon/voice.js` is ready to
   register purchased packs, boot variants) · Daily Bounties (3
   date-hash-rotated micro-objectives from real facts) · 6-week Seasons + NG+
   (windows over history, nothing resets) · Ember Shelter streak shield.

## Frontend half (this lane)

  nightfall}.json` + deterministic resolver + celebration-card wiring.
  Event keys already reserved: `cast_ok`, `cast_fail`, `break_nudge`,
  `ambient` (wired as their surfaces land).
- After Batch 1: delete fe threshold copies, read GCFG.
- After Batch 4: Shop / Bounties / Seasons surfaces (roundtable + legacy).

## Verification (per charter)

- Each batch: `node collector/collector.mjs && node collector/assemble.mjs`
  loop + golden re-baseline with its CONTRACT entry.
- Batch 2 regression check: run against the real history — assert no
  takeover fires from the migration event and level is unchanged.
- Batch 3: two consecutive runs over the same inputs → byte-identical
  outputs (determinism).
- Anti-anxiety rails hold: no countdowns, no loss-on-miss, mercy everywhere
  (streak shield is Batch 4's mercy mechanism).
